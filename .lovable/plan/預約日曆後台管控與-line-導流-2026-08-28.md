# 預約日曆後台管控與 LINE 導流

## 目標
讓首頁預約表單的月曆能根據後台設定自動顯示可預約 / 已額滿 / 不開放日期；預約資料仍導向官方 LINE；並提供一個簡易後台頁面管理日期與每日名額。

## 資料庫設計

### 1. `booking_availability` — 每日可預約設定
- `date` (date, PK) — 日期
- `max_slots` (int) — 每日最大可接案數，預設 3
- `is_blocked` (boolean) — 是否強制關閉，預設 false
- `reason` (text, optional) — 關閉原因（內部用）
- `created_at`, `updated_at`

### 2. `booking_requests` — 預約紀錄
- `id` (uuid, PK)
- `preferred_date` (date) — 期望檢測日期
- `inspection_type`, `property_type`, `region` — 表單選項
- `name`, `phone`, `email`, `address` — 聯絡資訊
- `status` (text) — pending / confirmed / cancelled
- `source` (text) — line / manual
- `created_at`, `updated_at`

## 權限規則
- 所有人（anon）可讀取 `booking_availability`：讓未登入訪客看到可預約日期。
- 所有人（anon）可新增 `booking_requests`：送出預約。
- 只有 `admin` 角色可讀取 / 修改 / 刪除 `booking_requests` 與 `booking_availability`。

## 前端變更

### Booking 表單
1. 載入時從後台抓取未來 90 天的 `booking_availability` 與當日已預約數。
2. `Calendar` 的 `disabled` 條件改為：
   - 過去日期
   - `is_blocked = true`
   - 已預約數 >= `max_slots`
3. 點選日期時若額滿或不開放，顯示對應提示。
4. 點擊「下一步」時仍將資料組成訊息，導向官方 LINE。
5. 同時在 `booking_requests` 新增一筆 pending 紀錄，作為名額計算依據。

### 新增管理後台 `/admin/bookings`
- 登入後才可進入（使用 `admin` 角色判斷）。
- 月曆檢視：顯示每日名額 / 已預約數 / 是否關閉，點擊日期可編輯。
- 預約清單：列出所有 `booking_requests`，可標記狀態。

### 新增管理後台 `/admin/availability`
- 批量設定未來日期：設定預設名額、關閉特定日期、開啟特定日期。

## 時程與驗證
1. 建立資料表與 RLS 政策（migration）。
2. 更新 Booking 表單讀取後台資料。
3. 新增預約寫入邏輯。
4. 新增 admin 頁面與角色判斷。
5. 用 Playwright 驗證：過去日期不可選、已關閉日期不可選、額滿日期不可選、預約後正確導向 LINE。

## 備註
- 為了先讓功能上線，第一版 admin 頁面會以簡潔表格與月曆呈現，不額外做複雜的權限 UI。
- 若日後需要自動同步國定假日，可再擴充。
